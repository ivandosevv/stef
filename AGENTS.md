# stef personal project

This is Ivan's personal open-source project. Keep all project files, build output,
test fixtures, and development work inside this repository. Do not read, modify,
connect to, or reuse code from SAPDevelop, Hyperspace, or other SAP projects.

The intended stack is Go (daemon), the official MCP Go SDK (stdio bridge), and
Svelte 5 / TypeScript / Vite / Tailwind (HUD). Runtime operation stays local.

The product name is stef. In VS Code, use its existing integrated browser editor
beside the agent; a native companion remains available for terminal and other
hosts. IDE plugins are optional experiments, not a required installation. Keep the
observer, lifecycle adapters, MCP contract, and IDE host separate. Passive file
tracking and hook ingestion must make no model calls. Respect the current workspace's Updates
setting: milestones reports only major steps with reasons, files captures and
explains each saved file revision, and disabled stops new recording/reporting.
Updates changes begin a new recording window (updates_from); automatic
explanations apply only to new saves, never to older retained pending files.
Read the mode once at task start and honor mode changes in receipts. In files
mode, prepare brief user-facing reasons alongside the edits, then after each edit
tool use exact pending IDs supplied by a trusted hook or get_state once with
settle_ms=300, and report_changes before another edit, test, or final reply.
Sequence edit, bounded check-in, and exact report in the same orchestration call
when available; do not return for another deliberation turn between them.
Include helpers, entry
points, tests, docs, configuration, and cooperating agents' edits. Check pending
changes once before finishing; leave unknown authors' intent unexplained.
Never claim that MCP exposes every client's private workflow.
Only mark individual agent/editor integrations supported after actual verification.
Choose the MCP setup client for the actual agent rather than its outer IDE.
The client catalog distinguishes project configuration from import exports;
never equate either with a real host connection or an opened IDE pane.
Default setup stays project scoped; do not guess project settings/hook schemas.
Ivan explicitly requested fixing Claude sessions launched from his home folder.
The opt-in scripts/connect-claude.py may register only stef through Claude's
native user-scope command and install a personal skill pointer, bound to an
explicit personal project. Preserve all other client settings. Never use the
home directory as an observer root or extend observation into excluded projects.
Keep the interface limited to the workflow, brief agent-supplied reasons,
directed arrows, a compact suggestion field, per-chat Clear, and the requested
small appearance picker (Dark, Light, Eye comfort, System), and compact Updates
picker (Major milestones, Every file, Disabled).
The Design picker offers Minimal or Interactive. Interactive renders the selected
revision's wrapped Git-style diff, local change exploration, or a milestone's
reported paths. Keep workflow and properties scrolling independent. Style-effect
samples must use supported exact captured values and clearly label their scope;
never invent arbitrary application behavior or execute source in the preview.
New live changes follow the newest step locally without moving keyboard focus.
Preserve open diffs and unfinished suggestions until inspection ends.
Design changes and history viewing make no model calls. Fuller context is requested
only through an explicit Explain more click. Request explanation asks for a
missing reason; neither action starts a background model call. Answer feedback with
report_event context_id for that retained step. Keep old history inspectable
without automatically generating or re-requesting its explanations.
Selected saved-file steps may open the requested Git-style diff with the exact
captured revision and its agent explanation. Keep it on demand, retain whitespace
and line numbers, and clearly identify truncated previews. Opening a diff must
make no model call and must not substitute the current file for historical data.
Keep closed steps to a file and short label; reveal the reason on selection and the
suggestion input on demand.
Each explicit set_session when enabling or starting/resuming a chat returns to
that worker's private workspace. Retain prior sharing only with the user's
explicit choice and resume_shared=true. Normal check-ins and reports never reset
sharing; do not rebind each turn. Use distinct
agent_id values and the original stable chat ID in set_session; retain its returned
origin session_id for all other tools. Bind before opening the verified endpoint
plus its returned view_path, so each agent sees its own workflow. Names are stable
local word pairs and numbers, never generated by AI; use workspace_name in user
messages and keep IDs internal. Share only through explicit set_workspace
create/join, passing the readable name or invitation ID to each cooperating worker. Leaving restores
private history. Shared get_state includes recorded brief reasons and authors, never
hidden reasoning. Include only actual own saved paths in changed_paths when trusted
hooks cannot provide exact revision IDs. Private views never follow another worker.
New chats start empty; resumed chat IDs restore their own saved workflow. Do not
reintroduce dashboards, replay bars, metrics, or code inspectors unless
the user asks. Distinguish chat identity signals from MCP transport connections;
never claim to detect a chat switch the host has not reported.

Default development and testing must watch examples/sandbox or an isolated
directory under .test-workspace. Use another repository only when explicitly
requested. Go unit tests may use standard temporary directories with automatic
cleanup. Do not install MCP configuration into other projects automatically.

Run make check and make test for functional changes. Run make build followed by
cd ui && npm run test:e2e when changing the daemon-to-browser path. Preserve the
distinction between observed filesystem changes and agent-provided rationale.

README.md describes the working version. docs/ROADMAP.md tracks future scope.
Keep both accurate; do not describe planned functionality as implemented.
